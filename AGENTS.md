# AGENTS.md — City Council Minutes

A handbook for anyone (human or agent) extending this pipeline. Read this before
touching code.

## What this project does

Liberates every signed set of Boulder City Council minutes, 2000–present, from the
city's Laserfiche WebLink portal (`\Central Records\City Council\Signed Minutes`,
folder id 10888) into linked tables of meetings, attendance, agenda items,
speakers, motions, and per-member votes.

```
Laserfiche ──discover──▶ inventory.csv ──sample/fetch──▶ PDFs (LFS) + manifest.csv
   ──Datalab /convert──▶ markdown (OCR) ──Datalab /extract──▶ extraction JSON
   ──tidy──▶ data/processed/*.csv + meetings.json ──score/audit──▶ data/audit/*.md
```

Each stage is idempotent and resumable; run them with `uv run python -m scripts <stage>`.

## Layout

| Path | What | Mutable? |
|---|---|---|
| `data/original/laserfiche/listings/<folderId>.json` | raw folder listings from the portal | re-listed only with `discover --refresh` |
| `data/original/laserfiche/inventory.csv` | one row per document found | regenerated by `discover` |
| `data/original/laserfiche/pdf/<year>/<entry_id>.pdf` | the minutes (Git LFS) | **immutable** |
| `data/original/laserfiche/manifest.csv` | hash, bytes, method, page count per PDF | append-only |
| `data/interim/datalab/markdown/<year>/<entry_id>.md` | Datalab OCR output | regenerate only on purpose |
| `data/interim/datalab/extract/<mode>/<year>/<entry_id>.json` | Datalab extraction, with citations + verification | keyed by schema version |
| `data/interim/datalab/runs.csv` | every Datalab job: pages, cost | append-only |
| `data/processed/` | the dataset (tables, nested JSON, provenance) | regenerated by `tidy` |
| `data/lookups/` | sample definition, hand-transcribed reference, member aliases | hand-maintained |
| `data/audit/` | accuracy and audit reports | regenerated |
| `certs/boulder-ca-bundle.pem` | CA bundle for the city's server | rebuild with `certs/make_ca_bundle.py` |

## Gotchas (learned the hard way)

1. **TLS.** `documents.bouldercolorado.gov` omits its intermediate certificate. All
   requests verify against `certs/boulder-ca-bundle.pem` (from the CU Info Science
   *Web Data Science Book*, ch. 9). Never use `verify=False`.
2. **Rate limit.** The portal stops answering after ~15 requests in a burst and
   recovers after ~5 minutes. `LaserficheClient` pauses every 12 requests and backs
   off 5.5 min on any failure. A full crawl therefore takes hours; run it in the
   background and let it resume from the listing cache.
3. **Two kinds of record.** Pre-~2008 minutes are *imaged* (scanned pages, no file).
   `ElectronicFile.aspx` returns an empty 200 for them; use the viewer's
   `GeneratePDF10.aspx` → `DocumentService.aspx/PDFTransition` → `PDF10/<key>/<id>`
   flow, which needs the session cookie `DocView.aspx` sets. Rendered PDFs get new
   bytes every time, so their SHA-256 is not stable — compare page counts.
   Faster: the browse page's bulk export (`ZipEntriesHandler.aspx/StartExport`) returns
   one ZIP with a PDF per entry, ~6–10 requests per 25 records. `fetch` uses it by
   default and falls back to per-entry downloads. The export job is bound to the
   session that started it.
4. **Folder layout changes.** Early years list minutes directly under the year;
   later years nest month folders (`01 JAN`, `09 SEPT`). `discover` walks recursively.
5. **Names carry the date, inconsistently.** `Minutes - Apr-01-2003`,
   `City Council Minutes - 2018-12-04`, `... - 12.01.20`. `parse_name_date` handles
   these; the extracted `meeting_date` wins when present and disagreements are flagged.
6. **Datalab checkpoints expire.** `extract` reuses the `/convert` checkpoint to avoid
   paying for OCR twice; if it has expired, it re-sends the PDF (and pays to re-parse).
7. **Balanced vs. fast extraction.** Balanced (~$15–35 per 1K pages) catches motions
   that fast (~$6 per 1K) misses. The sample runs both so the full-run choice is made on
   measured accuracy — see `data/audit/accuracy.md`.
8. **The hand-transcribed reference has errors** (e.g. the 2022-09-14 record lists the
   2021 council). Treat `accuracy.md` disagreements as things to adjudicate.
9. **Vote inference is deterministic and flagged.** The extractor records only stated
   votes; `tidy.infer_votes` fills in the rest from the meeting's roll call and marks
   those rows `vote_source = inferred`. It declines when counts don't reconcile.

## How to…

- **Pick up newly filed minutes:** `discover --refresh` (or `--refresh --years 2026`),
  then `fetch --scope all`, `convert --scope all`, `extract --scope all`, `tidy`, `audit`.
- **Change what is extracted:** edit `scripts/extraction_schema.py`, bump
  `SCHEMA_VERSION`, update `scripts/tidy.py`, `scripts/schema.py`, and
  `docs/data-dictionary.md` together. Old extractions are re-run automatically because
  their schema version no longer matches.
- **Fix a member name:** add a row to `data/lookups/member_aliases.csv`
  (`alias` as printed → `member` canonical last name).
- **Re-score:** `score` rebuilds per-mode tables under `data/interim/tidy/<mode>/` and
  writes `data/audit/accuracy.md`.

## Conventions

- Originals are immutable; all cleaning happens downstream.
- Provenance is a sidecar (`data/processed/provenance.csv`) keyed on `entry_id`, not
  repeated on every row.
- Tables validate against pandera contracts in `scripts/schema.py` before writing.
- `entry_id` is the join key everywhere and resolves to
  `https://documents.bouldercolorado.gov/WebLink/DocView.aspx?id=<entry_id>&dbid=0&repo=LF8PROD2`.
